# Enterprise AI Work
## Workflow 与 Agent 子系统详细 PRD

文档编号：EAW-PRD-WA-001 ｜ 版本：V1.0 ｜ 日期：2026-11-10 ｜ 状态：待评审

产品负责人：王天陆 ｜ 使用终端：PC Web ｜ 对应主文档：EAW-PRD-001 V1.0

产品定位：为企业知识问答、项目进度汇总、风险分析与整改协同提供可配置、可追溯、可恢复的智能任务执行能力。以 Workflow 承载确定性业务控制，以 Agent 承载证据范围内的分析和有限规划，以人工审核约束正式成果与业务写入。

本稿为主平台 PRD 的专项细化，需求表示目标产品行为。R1、R1.1、R2 沿用主文档的建设版本；具体框架、模型与数据库由技术评审选择，不作为历史实现事实。

## 01 产品目标与范围

### 1.1 要解决的问题

企业 AI 任务不仅需要“生成一段文字”，还需要明确输入范围、组织业务证据、执行规则、保留状态、完成审核并驱动后续业务。流程搭建者需要可复用模板，使用者需要知道当前步骤、失败原因与下一步操作，企业管理者需要控制工具、成本、权限和配置变更。

目标 G1：一类标准业务可按固定流程重复执行。G2：Agent 的行为有明确输入、证据、工具、预算和输出边界。G3：页面关闭、服务重启、接口超时后可恢复，且不重复产生业务结果。G4：人能审查正式成果并逐项确认有副作用的动作。G5：配置变更有测试、发布、回滚与效果证据。

### 1.2 范围与主平台关系

| 子系统 | 本文负责 | 主平台负责/依赖 |
| --- | --- | --- |
| Workflow | 模板、节点契约、变量、控制规则、实例与恢复 | 项目入口、业务表单、资料和台账 |
| Agent | 角色配置、上下文、计划、受限工具、结构化结果 | 项目权限、模型服务、业务对象 |
| RAG 配套 | 检索范围、证据封装、父子块上下文、引用校验 | 文件上传、解析索引、文档版本维护 |
| 工具配套 | 工具登记、参数 Schema、授权、超时与幂等 | 业务 API、连接凭据、外部系统 |
| 人工在环 | 暂停、审批单、版本校验、批准/拒绝与恢复 | 审核页面、项目角色、报告与整改状态 |
| 运行治理 | 日志、版本、预算、评测、告警 | 企业身份、存储、审计与通知服务 |

本专项不重写成员管理和项目台账 PRD，不在 R1 加入生产环境任意流程画布、任意代码节点或多 Agent 自由协作。对原主 PRD 的 RUN、AG、WF、APR、OPS 需求做细化；业务完成率、逾期口径和整改状态继续遵循主 PRD。

### 1.3 版本范围

| 版本 | Workflow | Agent 与配套 | 发布条件 |
| --- | --- | --- | --- |
| R1 / P0 | 内置知识问答、进度汇总、报告发布、整改流转；受控配置；持久状态与异常恢复 | 固定流程内的进度/风险分析 Agent；RAG 证据；工具白名单；人工审核；基础评测 | 核心闭环、安全、幂等、并发审核与恢复用例通过 |
| R1.1 / P1 | 一个企业只读连接、定时任务、参数增强 | 开放分析 Agent、计划确认、缺参澄清、受控增量检索 | 有限规划及预算边界通过留出集评测 |
| R2 / P2 | 可视化编排、并行与汇合、受控子流程 | 有明确收益的专业 Agent 协作、更多连接与模型策略 | 单 Agent 与固定流程收益已经验证 |

R1 的“配置”指表单修改允许字段并发布新版本，不能修改生产运行实例中的节点拓扑。R2 画布仅为储备，不作为 R1 的验收项。

## 02 用户、权限与关键场景

### 2.1 角色权限

| 角色 | 可以做什么 | 必须受哪些限制 |
| --- | --- | --- |
| 业务使用者 | 选择模板、填参、执行授权任务、查看本人/授权运行 | 不发布配置，不查看越权证据或他人私有运行 |
| 项目经理/审核人 | 审阅报告、处理待审、确认整改、授权范围内接管 | 审核和创建整改分开；当前项目权限必须有效 |
| 流程/Agent 运营 | 编辑草稿配置、调试、评测、提交发布、回滚 | 配置管理权不自动赋予全部业务资料读取权 |
| 工具管理员 | 登记连接、配置能力与凭据引用、停用工具 | 真实密钥不得出现在前端、提示词或运行正文 |
| 企业管理员 | 管理角色、配额、停用策略与审计授权 | 系统配置权与业务内容访问权分离 |

R1 角色可以由同一人兼任，但每次行为仍按对应权限校验并记录角色。配置发布权限单独授予；需要双人审批的企业列入部署策略，不默认所有企业必须增加审批角色。

### 2.2 模式选择

| 用户诉求 | 产品入口与模式 | 理由 |
| --- | --- | --- |
| “这个项目的验收标准是什么” | 知识问答 Workflow | 查询、检索、引用和拒答路径固定 |
| “生成 P1 项目本周进度汇总” | 固定汇总 Workflow + 分析 Agent 节点 | 数据读取、规则统计、审核固定；原因与风险需要语义分析 |
| “分析里程碑延期可能有哪些原因” | R1.1 开放分析 Agent | 查询次序和补充证据可能动态变化 |
| “把确认的风险安排给负责人” | 整改创建表单 + 确定性业务 Workflow | 负责人、日期和验收标准由人确认，写入可审计 |

入口明确展示模式。开放分析不能自动变成有写权限的通用代理；已有固定模板能够解决时，优先推荐该模板并由用户确认切换。

## 03 页面与交互规格

| 页面 | 区域与字段 | 关键操作/状态 |
| --- | --- | --- |
| WA01 模板中心 | 名称、用途、适用项目、输入要求、最新可用版本、维护者 | 使用、查看说明；无权限或停用时不可启动 |
| WA02 Workflow 配置 | 基本信息、固定节点列表、变量映射、分支规则、超时、版本 | 保存草稿、校验、调试、评测、发布、回滚；R1 无拓扑拖拽 |
| WA03 Agent 配置 | 目标、职责、提示词、输入/输出、知识范围规则、工具、模型配置、预算 | 试运行、查看结构化结果与证据、版本比较 |
| WA04 新建任务 | 项目、模板/Agent、周期、资料范围、审核人、数据检查 | 启动；R1.1 缺参澄清、计划确认；展示会读取什么 |
| WA05 运行详情 | 步骤时间线、当前状态、来源、调用摘要、成本、输出、错误 | 取消、重试、恢复、接管；普通用户与运营信息分级 |
| WA06 人工审核 | 具体成果版本、正文差异、来源、审核范围与确认动作 | 通过、退回、撤回、转交；过期版本禁止提交 |
| WA07 工具中心 | 工具名、类型、输入/输出、授权策略、连接状态、停用状态 | 测试、启用/停用；无“把密钥发送给模型”入口 |
| WA08 调试与评测 | 脱敏样本、版本组合、期望依据、判分、失败分类、耗时用量 | 运行样本、比较版本、导出有权结果、形成发布记录 |

共用交互：异步请求返回 run_id；刷新后恢复服务端状态；不展示无真实依据的百分比。用户看到“正在读取台账/检索资料/生成分析/等待审核”等业务步骤；运营可按权限查看节点元数据。错误信息包含原因、影响、可选动作和排障编号。

## 04 Workflow 管理需求

### WF-D01 模板定义与配置（P0）

用户故事：运营人员希望把高频业务固化为可重复使用的模板，业务用户不必编写 Prompt。

字段：workflow_id、名称（1～100 字）、场景、说明（≤2000 字）、输入 Schema、输出 Schema、节点定义、变量映射、分支规则、允许项目范围、版本、维护者、状态。R1 内置拓扑只读，允许编辑指定表单字段；编辑发布版时必须派生新草稿。

规则：未满足必填项、存在未知工具或无效变量时不能提交测试；模板当前企业可见范围不得扩大资料读取权限。模板名称可重复，ID 唯一；复制产生新 ID，保留来源，不复制运行记录、凭据或业务授权。

验收：同一发布版可由多名授权用户重复运行，每次拥有独立 run_id；复制模板不会沿用原作者的项目读取权限。

### WF-D02 变量与数据映射（P0）

变量类型支持字符串、数字、布尔、日期、枚举、对象、数组与对象引用。配置项含名称、类型、是否必填、默认值、枚举/长度/范围、来源和允许使用节点；字段重命名须列出受影响节点。引用格式采用节点输出路径，例如 metrics.overdue_tasks，前端可从合法字段列表选择，R1 不允许任意表达式代码。

配置校验确认字段存在、类型匹配、上游必经、空值策略明确。运行时再次校验，不能仅信任调试结果。日期缺失和数字 0 不得混为同一空值。tenant_id、actor_id、授权范围为系统保留变量，禁止在表单、Prompt 或节点输出中覆写。

验收：错误路径、把数组映射成字符串、引用未执行分支的必填值均在发布前拦截；运行中收到类型漂移则停止相应节点并给出可读错误。

### WF-D03 条件、分支与默认路径（P0）

R1 在内置节点中提供确定性条件：字段存在、枚举相等、数值比较、权限通过、证据可用、Schema 合格、审核决策。运算条件由后端执行；模型只能产生待校验的分析标签，不能决定是否免除审核。

每个条件节点必须有默认路径与失败路径。证据不足可生成“资料缺口 + 可验证数字”的降级草稿，仍需审核；结构化台账完全缺失则阻断进度汇总，不伪造业务指标。发布前校验所有路径可达、无悬空节点、终止条件明确。

验收：无相关资料走证据不足分支，工具失败走故障分支；不能把“无结果”当成接口成功且没有风险。

### WF-D04 配置版本与发布（P0）

配置状态：DRAFT → TESTING → PUBLISHED；测试失败返回 DRAFT；发布版可 DISABLED。保存草稿不影响线上。发布生成版本号与不可变配置快照，记录变更说明、操作者、测试集、评测结果、依赖工具及模型版本。

发布校验包括结构、变量、权限、工具可用性、预算、关键用例和回归门槛。回滚把“新运行默认入口”切回已验证版本；已经运行的实例继续使用绑定版本。工具撤销和安全权限更新即时生效，不能因版本固定继续使用已撤权能力。

验收：运行期间发布新版，旧实例保持旧配置；新实例使用新默认版本；禁用模板后历史可按权限查看，但不能新建任务。

### WF-D05 触发与定时（P0 手动；P1 定时）

R1 由用户在平台手动提交；每次提交使用 submission_key，同一键同参数返回同一 run_id，同一键不同参数返回冲突。用户主动“重新生成”创建新键与新运行。

R1.1 定时字段：触发规则、企业时区、项目、模板版本策略、数据周期、执行身份、审核人、启用状态、截止时间。采用明确服务身份与限定项目授权，不使用创建者长期个人会话。创建者离职、身份失效或授权撤销时暂停并告警，不自动换成管理员身份。

定时触发键 = schedule_id + scheduled_at；错过触发窗口 R1.1 默认只补最近一次并标记延迟，不无限回补；前一次仍运行/待审核时默认跳过并记录原因，避免堆积。定时仅自动生成草稿，不自动审核、发布或创建整改。

验收：同一触发事件重复投递只建一个实例；企业时区与夏令时变化按选定规则测试，不用客户端本地时区推算。

## 05 节点目录与执行契约

### 5.1 R1 节点类型

| 节点 | 输入 | 输出 | 关键约束 |
| --- | --- | --- | --- |
| Start | 已鉴权主体、项目、用户参数 | 合法输入与版本绑定 | 不信任客户端租户覆盖值 |
| ValidateInput | 输入 Schema、项目权限、数据要求 | 校验结论、缺失清单 | 缺必要事实阻断；局部缺失显式降级 |
| ReadSnapshot | 数据源、周期、截点 | snapshot_id、业务记录、质量说明 | 快照不可变；历史周期不能借用当前状态 |
| RuleCompute | 快照、规则版本 | 统计数字、规则风险初值 | 数字由代码规则计算，模型不能覆盖 |
| RetrieveEvidence | 查询、授权范围、文档版本 | evidence[]、缺口与冲突 | 权限过滤；空召回与服务故障分开 |
| AnalyzeAgent | 指标、证据、重点关注项 | 风险、可能原因、建议、缺失项 | 限定输入、工具与预算，结构化返回 |
| ValidateOutput | Schema、证据、规则数字 | 合格结果或错误清单 | 引用、数字、必填字段和权限均校验 |
| SaveDraft | 合格内容、来源与版本 | report_id/version/hash | 保存不等于正式发布 |
| HumanReview | 成果版本、审核人 | 审核单与决策事件 | 状态入库，等待不占执行线程 |
| PublishReport | 已批准版本、明确发布请求 | 正式成果与发布事件 | 写入前重验权限、版本和幂等 |
| CreateRectification | 另行确认的整改动作 | 逐项任务 ID/错误 | 报告通过不授权自动创建 |
| End | 成果/失败/取消结果 | 最终摘要、审计、通知事件 | 不隐藏未完成与部分失败 |

### 5.2 WF-N01 节点契约与状态（P0）

节点配置含 node_id、type、输入映射、输出 Schema、超时、可重试类型、最大重试、失败策略、敏感级别与执行权限。节点输出仅能更新其拥有的 State 字段，原始输入与既有证据不原地覆盖。

节点状态：PENDING、RUNNING、SUCCEEDED、FAILED、SKIPPED、WAITING、CANCELLED。SKIPPED 仅表示条件未选中且满足下游契约，不能代替 FAILED；WAITING 用于人工事件，不能被按“执行超时”判死。

验收：节点输入、输出、耗时、重试和错误能关联同一 run_id；下游在上游未成功或无合法降级输出时不得执行。

### 5.3 WF-N02 并行、循环和子流程边界（P2）

R1 固定拓扑采用顺序与明确条件；Agent 内部有限迭代不是任意 Workflow 环。R2 画布若支持并行，必须定义 all-success/允许部分结果的汇合策略、字段合并冲突规则、超时取消及错误归属；子流程必须绑定版本并继承或缩小授权。

禁止无终止条件的环、把多个分支写入同一业务对象却无并发规则、让子流程扩大工具范围。没有明确业务收益，不引入并行和多 Agent 以增加复杂度。

## 06 四条业务 Workflow 规格

### 6.1 W01 可信知识问答（P0）

触发：项目成员选择知识范围并输入问题。主路径：Start → ValidateInput → RetrieveEvidence → 回答生成 → ValidateOutput → 保存问答与引用 → End。此处是受约束生成步骤，不要求开放规划 Agent。

输入：question（1～4000 字）、project_id、kb_scope。输出：answer、answer_status、evidence[]、missing_information、trace_id。answer_status 为 SUPPORTED、INSUFFICIENT、CONFLICT；技术故障另记 FAILED，不能混成无答案。

无证据：说明缺失资料并停止企业事实生成。冲突：并列文档版本、生效时间和差异，无法判定时要求管理员确认。检索故障：提示稍后重试，不自动改用无依据的通用模型。R1 单轮；R1.1 多轮须重新校验历史与项目范围。

### 6.2 W02 项目进度汇总（P0）

触发：项目经理选择项目、周期、数据截点、知识范围、审核人并确认数据检查。主路径：Start → ValidateInput → ReadSnapshot → RuleCompute → RetrieveEvidence → AnalyzeAgent → ValidateOutput → SaveDraft → HumanReview → PublishReport → End。

规则数字：完成率、本期完成数、未完成逾期、逾期天数、里程碑及上期变化。规则遵循主 PRD；缺历史快照不生成历史比较，空任务集合不显示 0%，无截止日不猜测逾期。

分析输出包含风险事实、证据、可能原因、建议与待确认项；不直接生成已生效负责人指派。无文档证据时，已验证统计可保留，但原因与结论必须标缺口；未通过校验的模型文本不能进入正式发布。

报告退回后保持草稿修订链，提交新审核单锁定新版本；重新生成另建 run_id 并记录 parent_run_id。报告审核通过后仍需明确的发布动作，R1 可在“通过并发布”一次点击中表达两项授权。

### 6.3 W03 整改创建与业务流转（P0）

触发：项目经理在已发布报告中勾选风险，补齐负责人、截止日、验收标准并确认。创建操作不属于分析 Agent 的默认权限。

创建流程：校验当前项目与报告权限 → 冻结动作清单 → 用户确认 → 逐项幂等创建 → 返回成功/失败与任务链接 → 发站内待办。创建后的业务状态为 TODO → IN_PROGRESS → PENDING_ACCEPTANCE → ACCEPTED；退回进入 REWORK，未验收可由项目经理取消并填写原因。

报告运行和整改业务实例独立存在。不能因为报告重新生成或模板回滚而撤销既有整改；取消分析任务也不能自动删除已经提交的业务结果。

### 6.4 W04 开放风险原因分析（P1）

输入：目标、项目、时间范围、关注任务与可用资料范围。先识别缺失必填参数，有歧义时澄清；信息充足后形成计划供用户确认。分析循环为“选择受权读取工具 → 获取结果 → 更新证据与缺口 → 判断是否足够”，达到预算或证据足够即结束。

计划调整若只改变授权范围内查询顺序，记录原因后可继续；新增工具、扩大资料范围、增加预算或要求写入，暂停并请求新的明确授权。输出为原因假设、支持/反对证据、替代解释、信息缺口及建议验证动作，不伪装为已确定根因。

## 07 Agent 配置与管理需求

### AG-D01 Agent 定义（P0）

字段：agent_id、名称、用途、责任边界、允许场景、输入 Schema、输出 Schema、Prompt 版本、模型配置引用、知识范围规则、工具白名单、预算、维护者、启用状态。R1 内置“项目进度与风险分析 Agent”，R1.1 新增开放分析入口；不以多个 Agent 名称包装同一个未经评测的提示词。

Agent 定义不能包含实际业务凭据或固定越权账号。Agent 的资源授权来自当前执行身份、项目、资料与工具策略的交集。删除配置前检查依赖模板；被发布版引用的 Agent 只能停用或标弃用，历史定义仍可审计。

验收：从 Agent 详情可列出被哪些 Workflow 版本引用；未授权成员不能通过直接 ID 调用。

### AG-D02 提示词、模型与输出约束（P0）

提示词分为平台不可编辑规则、Agent 职责配置、业务输入、证据内容四区。运营只能编辑被允许的职责/风格/输出要求，不能关闭平台鉴权、审批或证据规则；用户文档中的指令只作为资料内容。

模型配置字段：已授权模型 ID、生成参数、上下文上限、输出上限、单次超时、是否允许备用配置。备用模型必须完成相同数据策略与回归验证，切换记录版本和原因；R1 默认失败后停止，未经显式配置不自动切换供应商。

结构化输出示例字段：summary、risk_items[]、evidence_ids[]、hypotheses[]、missing_information[]、recommended_actions[]。风险至少含描述、相关任务、等级建议、依据与事实/推断标签。模型不得覆写 rule_metrics、tenant_id、审批结果或已生效业务状态。

验收：模型输出未知字段或无效引用时不直接写入；输出不含“我已经创建任务”等未实际执行的声明。

### AG-D03 上下文与记忆（P0）

R1 只提供本次任务必要输入、规则结果、检索证据及被允许的工具摘要。超长上下文按明确策略裁剪：保留权限/任务目标/规则数字/关键证据引用；证据正文可压缩但保留对应 ID 与缺口标记，不能无提示丢弃冲突证据。

任务级 State 与历史业务成果分开；R1 不建立跨项目共享的个人长期记忆。复制运行仅复制允许参数，重新检索并鉴权；不直接复用旧会话中的敏感原文。R1.1 多轮会话切换项目须新会话或明确清除原项目上下文。

验收：两个租户、项目或用户的并发运行不会混用证据；超长资料导致裁剪时结果显示相应信息缺口。

### AG-D04 Agent 版本与调试（P0）

沿用 DRAFT、TESTING、PUBLISHED、DISABLED 生命周期。Prompt、模型、工具范围、知识策略、预算和 Schema 任一改变均形成新版本；运行绑定确定版本。调试使用专用样本与沙箱工具，写动作默认模拟，仅展示拟执行对象，不产生生产整改或外发。

调试页展示输入摘要、可见证据、工具调用参数、结构化输出、校验错误、耗时与用量；按权限脱敏。输出的是任务步骤与依据，不提供或要求模型内部思维链。调试成功不直接发布，必须通过对应回归门槛。

## 08 Agent 执行与计划需求

### AG-R01 任务理解与澄清（P1）

必填目标、项目和时间范围若缺失或存在多个解释，返回待澄清问题与可选项；已经明确的参数不反复询问。默认最多连续 2 轮澄清，仍无法确定则停止自动执行，保留草稿并建议用户补充。等待输入不计模型运行超时，但有独立到期策略。

目标超出能力时说明当前能处理的范围，例如只能提供证据分析，不能自动批准合同。用户改变项目/周期等关键参数时创建新分析上下文，不沿用已批准计划和旧证据权限。

### AG-R02 计划确认与计划变更（P1）

计划字段：plan_id/version、目标、步骤列表、每步工具/数据范围、预期成果、风险级别、调用上限、预计用量范围、待确认项。预计成本无法准确计算时标为估算或只展示上限，不保证精确价格与时长。

首次开放分析在执行前展示计划。用户可确认、调整目标或取消；只能编辑业务意图与允许参数，不能勾选未授予的工具。确认绑定计划版本与参数 hash；计划变更分为范围内重排和授权范围变更，后者产生新确认，不复用旧授权。

验收：用户拒绝计划后没有工具调用；计划确认后新增工具被拦截并等待重新确认。

### AG-R03 工具选择与有限迭代（P0 固定节点；P1 动态调用）

R1 由 Workflow 传入证据，Agent 默认不自主选择外部工具。R1.1 动态分析只能调用白名单内受权读取工具；调用前检查参数 Schema、当前项目、访问范围和预算，调用后校验结果类型、截断标记与错误分类。

建议默认：每任务工具调用上限 8 次、分析迭代上限 3 轮、活跃运行时间 300 秒；此为待压测配置。每次实际发起的工具请求都计次数，包括重试；被鉴权拦截未发出的请求不计工具执行次数，但记录策略拒绝。LLM 调用另记录次数与 tokens。等待人工不消耗活跃时间，恢复后沿用原累计预算，不能靠恢复清零。

重复相同查询且没有新增证据时停止或请求人工补充。遇到“证据足够、预算耗尽、用户取消、权限撤销、工具不可用且无法降级”之一时退出；部分结果显式标为未完成。

### AG-R04 结果、假设与行动提案（P0）

结果必须区分证据事实、规则结果、原因假设和行动建议。事实引用授权证据；原因假设展示支持证据、相反证据/缺失项，不输出未经验证的确定根因。没有可靠支持时返回“无法确认”，不把检索相似度当结论可信百分比。

行动提案只描述建议做什么与仍需确认的字段。R1 的创建整改入口由项目经理发起；Agent 不因建议被采纳而获得创建、关闭或改派的永久权限。

验收：输出风险时保留风险 ID、证据 ID、相关任务与待确认项；即便模型请求写工具，也被工具层拒绝并记录。

## 09 RAG 证据配套需求

### RAG-S01 读取与检索范围（P0）

检索身份取自平台上下文，范围 = 企业 + 项目 + 知识授权 + 文档生效版本 + 用户请求收窄范围。检索前过滤，引用预览与最终输出时再次校验；不能只在回答页面隐藏越权来源。

检索返回状态区分 FOUND、EMPTY、CONFLICT、FAILED；空召回不是系统故障。查询改写可扩展同义表达，但不能扩大项目或租户范围。模型不直接连接向量数据库。

### RAG-S02 父子块与证据封装（P0）

索引用子块定位相关片段，父段补充上下文；取回父段时继续执行 ACL 与版本检查。子块、父段、表格上下文分别保留 doc_id/version、chunk_id、parent_id、页/段锚点、有效期与授权信息；混合权限文档按最小安全片段处理，不能因父段扩展读到无权内容。

每条可进入模型的证据封装为 evidence_id、文档标题、版本、页/段、文本、更新时间、访问策略、检索信号。文档版本、索引版本与检索配置都记录到运行；原文引用必须由平台生成受控入口，不能由模型捏造 URL。

### RAG-S03 引用与证据校验（P0）

模型只允许引用本次证据集合内的 evidence_id。服务端校验存在、权限、来源定位、版本及结论支持关系；机械存在校验不能替代人工/评测集对“是否支持结论”的检查。未知 ID 拦截后允许一次格式/引用修复，仍不合格转人工。

来源删除或撤权时，依赖其内容的历史回答/报告也受限，不只删除链接。来源更新时旧报告保留版本标识并提示有新版本，不能把旧引用静默指向新内容。历史重放不恢复已经失效的访问权。

### RAG-S04 证据不足与冲突处理（P0）

没有依据不生成企业事实；只有规则数字时可产出数字与资料缺口，不生成无依据原因。版本冲突优先依据已确认的生效状态，无法判断则并列提示。补充检索受 Agent/运行预算约束，不能在无结果时无限扩展工具与资料范围。

验收：资料缺失、矛盾纪要、旧制度与有效新制度、撤权父段及表格定位各有固定用例。

## 10 工具与执行授权需求

### TOOL-S01 工具登记（P0）

工具字段：tool_id/version、名称、用途、读写分类、输入/输出 Schema、允许作用域、连接引用、超时、重试策略、幂等支持、结果查询接口、启用状态和维护者。R1 工具包括授权台账查询、证据检索、规则计算、报告发布与内置整改创建；Agent 的可调用集合是其中更小的授权子集。

工具描述可由运营维护，但真实授权以平台注册记录为准；外部返回的“新工具说明”不自动生效。HTTP/API、MCP 都是适配方式，不是绕过授权的通行证；R1 不以 MCP 接通为交付前提。

### TOOL-S02 每次调用的策略检查（P0）

检查顺序：账号/执行身份有效 → 租户与项目 → 工具状态 → 角色操作权 → 参数范围 → 预算 → 必要的人类确认。工具执行端必须再次校验对象权限，不只信任 AgentRuntime 已经检查。参数中非法 URL、内部网络地址、未知对象或超大响应按策略拒绝。

凭据在服务端解析，模型只看到工具别名和允许参数。响应脱敏、标注截断与过期，不能把工具失败正文当作事实证据。工具停用后阻断新调用，运行中下一次调用立即遵守停用状态。

### TOOL-S03 业务动作确认（P0）

写入确认绑定 action_id、对象/字段、参数 hash、操作者、项目、审核关联、确认时间和有效期。R1 整改创建确认建议 30 分钟内有效，到期或参数改变必须重新确认；长期报告审核等待不受此短时动作令牌替代。

授权范围包含完整动作清单，批量动作逐项返回结果；用户修改负责人、截止日期或验收标准后，新参数不能沿用旧确认。报告审核通过只批准该版本内容；创建整改是另一个明确动作。执行前权限和当前业务状态仍需复核，不能把批准视为永久许可。

### TOOL-S04 幂等、结果不明与补偿（P0）

幂等键由平台生成并持久化，业务 API 用唯一约束实现。对于已存在的相同键与相同摘要，返回原业务 ID；相同键不同摘要返回冲突。网络超时后优先通过原键查询结果，不重新生成键盲目写入。

未支持幂等或结果查询的外部写工具，R1 不开放自动执行。批量部分失败仅补失败项，不回滚或重复成功项。补偿必须是被授权的独立业务操作，不能让 Agent 私自删除已经创建的任务。

## 11 人工在环需求

### HITL-01 暂停与持久化（P0）

进入人工审核前保存 run_id、节点、报告版本/hash、审核单、证据与输入引用、版本组合和待办事件；然后释放执行资源。浏览器离线与服务重启不丢失等待状态。

报告审核建议 24 小时站内提醒、7 天标记长期未处理；不自动通过。审核人失效时转待转交，由有权项目经理处理。等待事件重复投递使用 event_id 去重；过期或已经结束的审核单不能重新激活流程。

### HITL-02 决策与恢复（P0）

通过/退回都绑定冻结报告版本，退回必填原因；修改需先撤回当前审核并创建新成果版本，提交新审核单。服务端校验最新权限、当前状态、expected_version、content_hash 和审核单决策状态。

通过后可进入发布阶段；发布失败保留已批准版本，重试前检查内容未变且当前权限有效，不重复批准同一正文。恢复可能重放节点入口，因此外部写操作位于独立幂等节点，不与“保存人工等待状态”混在一起。

### HITL-03 人工接管与撤回（P0）

接管分为补充资料、修订草稿、处理失败动作，不包含随意编辑运行数据库或绕过审核。人工修改保留原稿、修改者、时间和原因；修改后重新校验。

等待审核时取消运行须作废审核单；旧链接不可通过。撤回审核但保留任务时，run 继续处于 WAITING_REVIEW，内部 phase=WAITING_REVISION，前端显示“待修改”，不再向旧审核人发送有效待办。重新提交更新成果引用并进入新的审核等待阶段。

## 12 运行状态、恢复与取消

### 12.1 状态分层

WorkflowDefinition 是配置；WorkflowRun 是一次端到端业务运行；NodeAttempt 是一次节点尝试；ReportVersion 是成果正文；Approval 是一次审核；Rectification 是后续业务任务。各对象有独立状态，不以一个“完成”字段混用。

| 运行状态 | 含义 | 允许操作/退出 |
| --- | --- | --- |
| QUEUED | 已受理，等待执行 | 取消或调度进入 RUNNING |
| RUNNING | 活跃处理，phase 可为 ANALYSIS/PUBLISHING | 进入审核等待、失败、完成或取消中 |
| WAITING_REVIEW | 业务待审核；撤回修订使用 phase 区分 | 有效通过进入发布阶段；退回进入 REVIEW_REJECTED；取消作废审核 |
| REVIEW_REJECTED | 退回待修改 | 重提进入 WAITING_REVIEW；重新生成另建运行；可取消 |
| FAILED | 技术或校验故障，结果被保留 | 受控恢复增加 attempt；关键参数变化新建运行 |
| CANCELLING | 已阻止新步骤，等待处理中调用收敛 | CANCELLED；无法安全收敛则 FAILED 并提示 |
| CANCELLED | 终止，不继续执行 | 复制参数新建；已提交业务写入单独处理 |
| COMPLETED | 最终结果完成发布归档 | 只读查看/导出；修订另建版本 |
| WAITING_INPUT / WAITING_PLAN | R1.1 缺参澄清/计划确认 | 是 P1 对公开状态接口的扩展，旧客户端需兼容 |

分析子节点完成只表示草稿已形成，不等于 WorkflowRun 完成。主平台状态表未单列的“批准后发布中”，用 RUNNING + PUBLISHING 细化；COMPLETED 仍只在发布成功后生效。

### RUN-S01 重试、恢复与错误分类（P0）

临时网络、429 与 5xx 最多自动重试 2 次，建议 2 秒、5 秒退避并加抖动，遵守服务端限流提示和总预算；401/403、Schema 入参错误与缺必需数据不自动重试。LLM 输出格式允许修复 1 次，修复也计入模型用量。

检查点保存已完成节点、输入/输出引用、活动版本、预算、审批关联与副作用结果。恢复校验权限与依赖状态；纯计算可重放，业务写先对账。原快照不可用或参数改变时，停止原恢复并引导新建任务。

错误至少分 INPUT_INVALID、PERMISSION_DENIED、SOURCE_UNAVAILABLE、RETRIEVAL_FAILED、MODEL_TIMEOUT、OUTPUT_INVALID、BUDGET_EXCEEDED、VERSION_CONFLICT、WRITE_RESULT_UNKNOWN。展示业务提示与 trace_id，不向成员暴露堆栈和密钥。

### RUN-S02 取消与并发控制（P0）

取消请求先持久化，再阻断新的节点/工具调用。未返回的只读调用允许被中止或等待超时，但其结果不触发后续执行。取消和写入竞争时，服务端比较状态/版本并记录已获准或已拦截结果。

已提交的报告/整改不自动回滚。取消详情列出已提交对象、未执行动作和需人工核对的结果不明项；不把“点击取消”伪装成所有副作用已撤销。重复取消返回当前结果，终态禁止恢复。

### RUN-S03 队列、预算与资源隔离（P0）

按企业/项目限制活跃任务、模型和工具并发；超过并发进入队列并展示等待，不吞掉请求。硬配额耗尽阻断新模型任务，但历史读取、审核和人工整改应可用。等待人工不占 Worker 并发名额。

建议测试基线：5 个并发汇总、20 个并发问答；机器任务生成的延迟目标沿用主 PRD。排队、活跃处理、人工等待、重试和发布分别计时；不能将人工等待计入模型处理 SLA。

## 13 数据与接口契约

### 13.1 必要对象

| 对象 | 必要字段 | 不可破坏的约束 |
| --- | --- | --- |
| WorkflowDefinitionVersion | definition_id、version、nodes、mapping、policy、status | 发布不可原改；绑定依赖版本 |
| AgentDefinitionVersion | agent_id、version、prompt、model_ref、schemas、tools、budget | 工具白名单不代表最终用户有权调用 |
| WorkflowRun | run_id、parent_run_id、actor、project、snapshot、versions、state、phase | 输入版本冻结；业务阶段可持久恢复 |
| NodeAttempt | node_id、attempt、input_ref、output_ref、time、error | 尝试可追溯；不覆盖历史结果 |
| AgentPlan | plan_id/version、steps、scope、budget、hash、decision | 超出原范围变更须重新确认 |
| ToolInvocation | invocation_id、tool_version、input_hash、status、idempotency_key、result_ref | 同一逻辑动作结果稳定 |
| HumanCheckpoint | checkpoint_id、run、object_version/hash、reviewer、decision | 审核与动作批准分别保存 |
| EvidenceBundle | bundle_id、evidence[]、ACL、doc/index versions、query_ref | 引用必须属于本次授权集合 |
| EvalRun / AuditEvent | versions、dataset_version、scores、trace、actor、event_id | 样本版本与发布结论可追踪 |

运行 State 至少包含：身份与权限引用、项目与周期、数据截点、快照、文档/配置版本、规则数字、证据集合、风险项、成果版本、审核单、工具范围、累计预算、节点状态、错误与 trace_id。大文件保存引用，不把所有原文塞进 State 或 Prompt。

### 13.2 接口语义建议

| 操作 | 必要输入 | 结果与一致性要求 |
| --- | --- | --- |
| 创建/更新配置草稿 | 定义、版本基线、允许字段 | 配置 ID/version；并发修改返回冲突 |
| 校验/调试配置 | 草稿版本、样本、沙箱范围 | 结构问题、调试 run_id；不产生生产写入 |
| 发布/回滚配置 | 目标版本、评测记录、变更说明 | 新默认入口与审计；已有运行不改版本 |
| 启动运行 | 模式、项目、参数、submission_key | 202 + run_id；重复键相同请求不重复启动 |
| 查询运行/节点 | run_id、访问主体 | 状态、phase、步骤与权限内摘要 |
| 确认计划（P1） | plan_version/hash、decision、expected_version | 重复事件幂等；失效计划不可恢复 |
| 审核决策 | approval_id、object_version/hash、decision、decision_key | 当前权限和版本核验；相反并发决策仅一个生效 |
| 确认业务动作 | action_id、完整参数 hash、确认令牌 | 写入前复核；参数变更需重新确认 |
| 取消/恢复 | run_id、expected_version、原因、恢复点 | 取消不可绕过；恢复不清空预算和审计 |

接口路径由技术评审统一，以上行为语义为验收约束。事件使用稳定 event_id，业务写与通知事件可靠衔接，通知失败不能再次创建业务对象。

## 14 可观测、评测与安全需求

### OBS-S01 运行可观测（P0）

运行中心按企业、项目、模板/Agent 版本、状态与时间筛选，展示任务总量、活跃/等待/失败、节点错误分布、工具成功率、生成与端到端耗时、输入/输出 tokens、单次成本与预算命中数。无单价配置只显示用量，不编造金额。

Trace 关联配置、输入快照、证据、调用、成果、审批与业务写入结果。普通使用者只看业务摘要；敏感参数和原文仅授权排障人员可访问，仍遵守源资料权限与保留策略。

### OBS-S02 回归评测与发布门槛（P0）

每次改变 Prompt、模型、检索配置、工具/规则或状态逻辑，跑相关回归集；权限、未确认写入、重复写入、审批冲突是始终必跑集。评测保存数据版本、gold 依据/数字、允许动作、标准结果、判分和评审人。

建议质量门槛：固定统计集正确率 100%；虚构引用 0；引用有效并支持结论 ≥95%；权限/未确认写入用例全部通过；核心状态恢复与幂等全部通过。业务问答准确率和运行完成率沿用主 PRD，样本量与失败类型同时披露。模型评分不能作为安全及业务写入的唯一判断。

### OBS-S03 安全与审计（P0）

平台指令、用户任务、文档内容和工具响应分层处理；对输入和输出做格式与危险内容检查。工具网络目标受限，防止读取本机/内网敏感端点；模型工具申请不授予额外权限。Markdown 禁执行脚本，日志与下载不暴露密钥。

审计覆盖配置变更、调试、发布/回滚、运行触发、证据读取、工具请求、权限拒绝、预算停止、审核、取消恢复与业务结果。审计授权与业务内容权分离；历史记录不可由普通用户改删。

## 16 交付计划、依赖与待评审项

### 16.1 实施顺序

A：先固化对象、角色、规则、状态和错误字典；B：实现 W01/W02 的数据、RAG、分析、校验与草稿；C：接入审核、发布、整改幂等及运行恢复；D：补齐配置版本、调试、评测与监控；E：R1.1 验证有限规划、定时和一个只读连接。每阶段有可执行用例，避免只完成配置页而没有真实执行链路。

前置资料：脱敏项目台账、会议纪要、有效制度与冲突样本；项目经理/审核人；模型与检索服务；业务 API 的幂等和结果查询能力；身份、存储、通知及审计接口。任务分工与开发排期由研发评估后确定，不根据文档页数推算工期。

### 16.2 待评审决策

| 事项 | 本稿默认建议 | 责任/影响 |
| --- | --- | --- |
| R1 配置权限 | 运营表单配置，内置拓扑只读 | 产品/研发：决定编辑范围与发布校验 |
| Agent 工具能力 | R1 不自主外调；R1.1 仅受限读取 | 产品/业务：控制首期复杂度与授权边界 |

| 审核与动作期限 | 审核 24 小时提醒、7 天待处理；动作确认 30 分钟有效 | 业务：按任务风险调整，禁止自动通过 |
| 定时积压策略 | 前序运行/待审则跳过，只补最近一次 | 业务/产品：避免重复报告与待办堆积 |
