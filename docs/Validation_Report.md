## 结论与交付范围

首个纵向切片已实现并本地验证：**内置台账/CSV → 不可变快照 → 确定性统计与演示风险建议 → 人工修订/审核发布 → 独立确认整改 → 负责人处理/提交证据 → 退回/重提/验收**。五类页面均调用真实持久接口；没有以静态页面代替业务流转。

这是两份 PRD 的 R1 首个 MVP 切片，不代表全部 R1 P0 已完成或具备生产发布条件。分析为 DEMO_RULES，实际 LLM 调用/tokens 均为 0；真实模型、文档语义检索与知识问答未接通。没有声明真实风险识别质量、RAG 命中率或生产性能。

## 浏览器实际操作

使用同一个 ego-browser 任务空间，通过可见页面操作，完成：

1. `manager` 登录，看到 10/4/40%/2，发起汇总并打开运行详情。
2. 撤回原稿审核，填写人工修订、修改原因，保存 v2，重新提交审核。
3. 核对并发布 v2；另行选择风险，填写负责人/截止日/验收标准，核对最终确认清单并明确创建。
4. `owner` 登录，开始处理、提交文本证据；经理退回，负责人补证重提；经理验收。刷新后仍为 ACCEPTED v6。
5. 两端同时编辑：B 端先保存，A 端旧版本保存 409；A 端弹窗和未保存输入保留。实际排障号 `http_0b4537862bac4a40`，见 `browser-checks.json`。
6. 查看历史 v1 时审核按钮禁用，切回当前 v2 恢复；旧服务器接口亦有版本/hash 校验。
7. 台账页面导入非法 CSV，下载真实错误清单；编辑 T-010 后刷新可读回，已发布报告的 E-T-010 引用仍显示旧标题，证明冻结证据没有被当前台账覆盖。
8. 浏览器实际下载正式 Markdown，含审核状态、版本、规则口径、导出人和来源。
9. 1366×768 下查看总览、报告、运行与整改详情；683 CSS 像素宽附加检查无页面级横向溢出（表格有独立滚动容器）。此项不等价于完整 200% 缩放或移动端验收。
10. `owner` 直接打开未发布报告，界面拒绝且不保留报告正文/侧栏项目计数；重新登录经理后仍是 40%/2。见 `browser-auth-final.json`。

重启前后首次完成样本的业务对象 ID、版本、状态完全一致：`restart-before.json` / `restart-after.json`。第二次升级重启保留业务对象，并按已有审批/事件修正早期审核节点的过程状态；最终状态在 `local-final-state.json`。
